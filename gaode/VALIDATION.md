## 2026-10-26 修订：工具选择与单轮边界

修订依据（均为本轮核对所得）：官方题面要求步行耗时必须来自步行路线；高德 MCP 实际同时提供“距离测量”和“步行路线”，前者同样返回 `distance`/`duration`，且 `type` 可写“步行”；官方 `2026-competition-ecosystem` 分支的 `gaode/` 下只有空目录，格式规范以题面为准。

本轮改动 5 处，未重写既有正确内容：

1. 增加工具名对应表（周边检索 / 关键词检索 / 详情 / 地理编码 / 步行路线），步行路线优先坐标版，`..._by_address` 仅在坐标版不存在时使用。
2. 显式禁止用 `maps_distance`、驾车、骑行、公交代替步行路线；即使 `type` 写“步行”也不行。
3. 起点只有地标名时先做地理编码再继续；坐标与用户所说城市不符时以坐标为准并说明；单轮任务不以反问结束。
4. 候选核实按搜索远近顺序进行，约 8 个为上限，避免对全部候选无节制地查路线。
5. 推荐理由必须含该地点实测数字；距离短不得推断安静、座位或久坐。

## 本轮发现并修正的真实缺陷

J 首轮回答在推荐理由里写“更适合久坐一下午”，而同一份回答的说明段又写安静与久坐“未核实”，前后矛盾——这是用路程数据推断环境属性。已在 `SKILL.md` 输出节加入规则：距离短只说明好到达，不能推断安静、环境好、座位多或适合久坐。修正后同一场景复测通过，理由改为“安静程度、座位是否充足及能否久坐均为未核实”。
