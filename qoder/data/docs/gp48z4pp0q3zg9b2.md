## Q：为什么我的赛题排队时间比较长，什么时候才能轮到我判题

## Q：在提交 PowerContext 的 PDF 相关题目时，为什么我无法获得有效分数
A：PowerContext 所有赛题都提供了完整的题面和检查清单，以及部分用于自测的公开用例，如果存在无法得分的情况，主要的原因是编写的代码对于公开用例进行了过量的优化，在隐藏测例中没有起到效果，另一个占比较高的原因是变更了题面中的一些基本约束和接口，导致无法正确对接测评，请在实现时不要随意变更约定接口和修改自测用例代码，以免本地测评情况无法正确反应题目约束。

+ **先检查提交信息。**仓库须能被判题端读取，分支和 commit 须已推送且匹配，尤其不要将 branch 与 commitId 填反。
+ **按题面实现完整接口。**多个题目反复出现缺少指定模块、导出接口或返回结构不符合要求，导致测试尚未开始就失败。
+ **不能只验证一次正常调用。**常见问题集中在重启恢复、失败重试、重复输入、取消并发请求、缓存和计费等边界行为。
+ **真实数据链路必须跑通。**重点检查 Source 身份与版本、scope 隔离、持久化、引用回查，以及要求的原生检索路径，局部函数通过不代表整体通过。
+ **检索和上下文质量还需达标。**PDF 常见召回不足；混合检索、证据选择和增量上下文题，也存在候选排序、证据保留、预算控制及增量重建不符合要求的情况。

## Q：Qoder 的判题为什么提测中时间较长没有返回结果
Qoder 的赛题在判题时会进行环境准备和宣称功能的满足性检查，所以需要较长的判题时间，在早晚高峰期间可能会存在一定的积压情况，我们已经加大了判题的规模，以尽量及时处理积压题目，在 10 月 28 号已经达到了正常水位。目前基本处于随提随测的状态。

另外对于 Qoder Sites 发布不满足或者宣称功能不满足的情况会计为 0 分。

+ **网站不符合要求**：提交的不是公开 Qoder Sites 网站，或网站展示内容与提交代码不对应。
+ **项目无法启动**：缺少源码或配置文件，依赖不存在或冲突，调用的 SDK 接口不兼容。
+ **初始化失败**：未创建业务数据库、错误判断连接状态，或重复创建集合，导致首次运行或重启失败。
+ **数据无法正确复用**：错误解析查询结果，保存的数据或记忆无法用于后续功能。
+ **没有真实组件接入**：实际使用自制 SQLite、JSON 或内存实现，未接入 seekdb／PowerContext。

## Q：Dify 的判题进度如何，执行失败有哪些常见原因
Dify 目前的判题进度处于稳定推进的状态，并且此前的积压水位已经得到了解决，目前基本能做到提交后很快进入提测队列。

+ **提交信息错误**：分支或提交未推送、SHA 复制不完整、branch 与 commit 填反，或私有仓库缺少有效读取授权。
+ **交付材料不完整**：缺少 Dify DSL、配套源码、运行说明或验证样例，依赖作者本地未交付的数据和配置。
+ **DSL 无法正常执行**：节点缺少必要字段、变量引用错误，或导出的工作流与实际运行版本不一致。
+ **项目无法启动**：安装来源错误、依赖或 SDK 接口不兼容，未等待服务就绪便发起请求，导致首次启动失败。
+ **服务无法连通**：Dify Cloud 或容器访问了错误的 localhost 地址，临时隧道失效，或鉴权、网络配置未说明。
+ **记忆没有实际复用**：固定写入示例文本，未保存玩家真实输入；或读取结果未参与后续互动，无法验证跨会话效果。
+ **没有真实组件接入**：使用 mock、自制 SQLite、JSON 或内存代替声明的 seekdb／PowerContext；但 PowerContext 自身使用 SQLite 持久化符合要求。
+ **验证范围不足**：只有 YAML 检查、单元测试、mock 或截图，尚未完成真实 Dify 与指定组件的完整运行验证。
