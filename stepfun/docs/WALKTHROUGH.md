# 验证样例（评审照着做即可）

> 全部步骤都在本机跑通过。启动方式见 [../README.md](../README.md) §4。
> 应用入口：**http://127.0.0.1:8080**

## 0. 初始状态

**知识库的初始状态 = seekdb 里的集合表存在、但一行数据都没有。**

```bash
curl http://127.0.0.1:8080/api/schema | head -30
# -> "rowCount": 0
```

页面上的「查看 seekdb 表结构」按钮也能直接看到这个空表。

## 样例 1：完整流程（导入 → 向量化 → 写入 → 检索 → 展示）

**步骤**

1. 打开 http://127.0.0.1:8080
2. 「1 · 端侧模型」区域，dtype 选 **fp32**，点 **加载模型**
   - 顶部横幅会显示「当前推理后端：WEBGPU」或「WASM」
   - 首次会加载本地模型（约 1.3 秒）
3. 「2 · 导入语料」区域，点 **填入示例语料**（自动填入 12 段露营主题的中文文本），点 **本地向量化并入库**
   - 状态栏会依次显示：本地切块 N 段 → 向量化完成（xx ms）→ 入库完成 · 新增 N 段 · 写入 xx ms · 索引刷新 xx ms
4. 「3 · 混合检索」区域，查询框输入 `热牛奶多少钱`，点 **搜索**

**预期表现**

- 结果区出现若干条，每条带排名、文档 id、距离分数、原文、元数据
- 状态栏显示：`命中 N 条 · 查询向量化 xx ms · seekdb 检索 xx ms · 融合方式 RRF · 含全文腿`
- 点「4 · 数据与证据 → 导出行级数据」，能看到**原文和元数据确实存在 seekdb 里**

**判定**：能检索出与「热牛奶」相关的文本即为通过。

## 样例 2：跨会话记忆（同一个浏览器，换一次「会话」也能记住）

**步骤**

1. 在样例 1 的基础上，点 **清空知识库（回到初始状态）**
2. 点 **填入示例语料** → **本地向量化并入库**
3. 查询 `热牛奶多少钱` → 记下返回的第一条原文
4. **刷新整个页面**（F5）—— 这模拟「换了一个新会话」
5. 重新 **加载模型**，再查一次 `热牛奶多少钱`

**预期表现**

- 刷新后界面显示「当前推理后端：…」，知识库里的数据**还在**（数据在 seekdb 里，不在浏览器里）
- 第二次检索能召回与第一次相同的文档；点「查看 seekdb 表结构」能看到 `rowCount` 仍是导入的段数

**为什么这证明记忆来自 seekdb**：页面刷新后浏览器里的一切都清空了，检索结果仍然正确 —— 说明状态真的落在数据库里，而不是浏览器内存。

## 样例 3：向量 + 全文的混合召回

**步骤**

1. 导入全部 64 段示例语料（点「清空知识库」后，用 `bench/corpus/corpus.json` 里的 64 段，或者手工粘贴多段）
2. 查 `睡袋受潮以后还能保暖吗`

**预期表现**

- 排在前面的应当是「羽绒睡袋受潮之后几乎完全失去保暖能力…」这类**睡袋**主题的文档
- 这类中文问句在**纯关键词**检索下很难命中（全文腿需要靠 ik 分词把「睡袋/受潮/保暖」都切出来），靠**向量腿**才召得回来 —— 两腿都在起作用
- 想看融合细节：状态栏的「融合方式 RRF · 含全文腿」

**补充验证**：把「3 · 混合检索」和「4 · 数据与证据 → 查看 seekdb 表结构」对照看，能确认 `idx_fts`（ik 全文索引）与 `idx_vec`（VSAG HNSW 向量索引）**两个索引都在**。

## 样例 4：增量导入

**步骤**

1. 在已有数据的基础上，往「2 · 导入语料」的文本框里**追加**一段新文本，例如 `今天新增一条：热牛奶买一送一。`
2. 点 **本地向量化并入库**
3. 再查 `热牛奶`

**预期表现**

- 状态栏显示「新增 1 段 · 写入 xx ms · 索引刷新 xx ms · 库内共 N 段」（N 比之前 +1）
- 新的那一段能被检索到
- 点「导出行级数据」能看到新增的那行

**判定**：增量写入后**刷新索引**才能被检索到（这是 seekdb 异步索引的要求，代码里已自动调用 `refresh_index()`）。

## 样例 5：玩家隔离 / 会话状态互不干扰

**步骤**

1. 清空知识库，导入示例语料
2. 查 `热牛奶多少钱`，记下结果
3. 点 **清空知识库** → 确认 `rowCount` 变 0
4. 重新导入**另一批**文本（例如只导入「导航」主题的 8 段）
5. 再查 `热牛奶多少钱`

**预期表现**

- 第二次查「热牛奶」**不应**返回第一次那批的文档（库里已经没有它们了）
- 结果反映的是当前知识库的内容 —— 集合状态与当前数据一致

## 样例 6：量化与后端切换（性能与质量对比）

**步骤**

1. 在「1 · 端侧模型」区域依次选 **fp32 / fp16 / q8**，每次点 **加载模型**
2. 每次加载后导入语料、跑同一批查询
3. 勾选「**强制降级到 WASM**」再跑一遍（验证降级路径）

**预期表现**

- 每次换 dtype 后，状态栏里的模型 dtype 会变
- 强制 WASM 时顶部横幅变成「当前推理后端：WASM · 已按要求强制降级到 WASM」，**功能完全可用**
- 精度与体积的对应关系（模型文件在 `web/public/models/` 下）：

| dtype | 模型文件 | 体积 |
| --- | --- | --- |
| fp32 | `onnx/model.onnx` | 94,851,877 B |
| fp16 | `onnx/model_fp16.onnx` | 47,497,427 B（1.997×） |
| q8 | `onnx/model_quantized.onnx` | 24,010,842 B（3.950×） |

- 完整的量化前后质量与耗时对比见 [../bench/results/quality.md](../bench/results/quality.md)

## 样例 7：端侧合规自证

**步骤（命令）**

```bash
cd stepfun
node scripts/check_compliance.mjs
node scripts/check_api.mjs
```

**预期表现**

- `check_compliance.mjs`：**104 项全部 PASS**。其中包括「服务端只有 seekdb 一个运行时依赖」「服务端源码里没有任何模型包与云端推理域名」「服务端没有自实现的 merge/rerank/score/rank 函数」「Schema 里 `embeddingFunction: null`」「写入后调用 `refresh_index()`」「查询向量由浏览器传入」
- `check_api.mjs`：**29 项全部 PASS**。覆盖健康检查、重置、写入、维度校验、混合检索、表结构与索引、行级数据、增量导入、重置回初始状态

**浏览器端**：`bench/raw/bench-raw-*.json` 里的 `externalRequests` 字段为空数组 —— 整个基准过程**没有发出任何外部请求**，证明没有调用云端推理 API。

## 如何恢复初始状态

任何时候想回到「表存在但没有数据」的初始状态，三种等价做法：

```bash
# 方式 1：页面上点「清空知识库（回到初始状态）」
# 方式 2：接口
curl -X POST http://127.0.0.1:8080/api/reset

# 方式 3：直接清空物理表（保留表结构与索引）
docker exec stepfun-seekdb mysql -uroot -pStepFun@2026 -h 127.0.0.1 -P 2881 \
  -e "DELETE FROM stepfun_kb.\`c\$v2\$<collection_id>\`;"
```

方式 1、2 走的是同一个实现：删数据行 + 刷新索引，**表结构与索引保持不变**，所以每次复现实验的起点完全一致。
